# AI-Based Malicious URL Detection System

A machine-learning web application that inspects website URLs, extracts lexical and structural indicators, and classifies links as **SAFE**, **SUSPICIOUS**, or **MALICIOUS** using an ensemble Random Forest model with transparent risk factor explanations.

## 1. Overview & Core Concept

### What It Does
When a user suspects a link in an email, SMS, or social media post, they paste the URL into the detector. The system:
1. Validates the URL structure without ever visiting or pinging the malicious target (zero risk of malware drive-by download).
2. Deconstructs the URL into 18+ mathematical and lexical features (domain depth, IP usage, punycode, entropy, phishing tokens, symbol frequencies).
3. Evaluates the feature vector through a trained **Random Forest Classifier** ensemble.
4. Outputs the classification (**SAFE**, **SUSPICIOUS**, or **MALICIOUS**) with probability scores.
5. Displays a visual risk breakdown explaining which specific features triggered warnings and provides clear defensive recommendations.

### Target Audience & Hackathon Persona
- **Hackathon Judges & Evaluators**: Looking for real machine learning models (not hardcoded `if-else` hacks), transparent mathematical explanations, clean UI, and well-structured code.
- **Everyday Web Users & Students**: Needing simple, clear guidance on whether an unfamiliar link is safe to click.

## 3. Key Product Decisions & Trade-Offs

### Decision 1: Live In-Browser Model Engine + Exportable Python Files
- **Chosen Approach**: Build the full interactive web application with a live, real Random Forest evaluation engine inside the applet, while also providing a complete, ready-to-run Python/Flask + Scikit-Learn project repository inside a dedicated "Python Backend & GitHub Code" view.
- **Why**: AI Studio runs Node.js/TypeScript on port 3000. Running the interactive classifier in the web app ensures zero downtime, zero network latency, and instant responsiveness for hackathon judges, while providing the exact Python code requested in the problem statement for GitHub submission.
- **Alternative Considered**: Running a separate Flask sub-process on an internal port with proxying. Risk: If Python dependencies fail or port conflicts arise during judging, the app breaks. The dual-path gives 100% reliability plus full Python export.

### Decision 2: 18 Comprehensive URL Lexical Features
- **Chosen Approach**: Extract 18 concrete lexical, structural, and heuristic features:
  1. `url_length`: Overall character count.
  2. `domain_length`: Hostname length.
  3. `dot_count`: Number of '.' dots.
  4. `subdomain_count`: Depth of subdomains.
  5. `has_ip_address`: Whether the host is a raw IPv4/IPv6.
  6. `has_at_symbol`: Presence of `@` credential confusion token.
  7. `has_double_slash_redirect`: `//` appearing in the path.
  8. `hyphen_count`: Multiple hyphens often used in typosquatting.
  9. `is_shortened`: Known shortener domain (bit.ly, t.co, tinyurl, etc.).
  10. `suspicious_keyword_count`: Match against security/phishing lexicon (`login`, `verify`, `banking`, `secure`, `update`, `paypal`, `wallet`).
  11. `has_https`: Whether HTTPS is used (with proper nuance).
  12. `digit_ratio`: Ratio of numeric digits to alphabetic letters.
  13. `special_char_count`: Count of `?`, `=`, `&`, `%`, `_`, `-`.
  14. `path_depth`: Number of slash segments.
  15. `query_length`: Length of query string parameters.
  16. `entropy`: Shannon entropy measuring URL character randomness (used by domain generation algorithms / DGA).
  17. `has_port`: Explicit non-standard port in URL (e.g., `:8080`).
  18. `tld_reputation`: Evaluation of high-risk top-level domains (`.xyz`, `.top`, `.tk`, `.ru`, etc.).

### Decision 3: Real Random Forest Algorithm Architecture
- **Chosen Approach**: A true ensemble of multiple Decision Trees. Each tree evaluates subsets of features and votes. The aggregate forest computes real probability distributions across classes (`P(Safe)`, `P(Suspicious)`, `P(Malicious)`).
- **Why**: Decision trees and random forests provide clear decision paths and feature importance scores, fulfilling the requirement for transparent explainability without opaque black boxes.
